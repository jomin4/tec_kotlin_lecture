# 🗂️ lazy vs lateinit 정리

> 고급 섹션2(지연과 위임) 강의1 요약. 관련: `section10/Lesson01.kt`, `section10/LazyInPractice.kt`,
> `section10/InjectionStyles.kt`, QnA Q14, `diagrams/s10l01_lazy.svg`.

## 1. 핵심 비교

| 항목 | `by lazy { }` | `lateinit var` |
|---|---|---|
| **한 줄 의미** | 값을 **처음 쓸 때** 계산해서 캐시 | non-null인데 **값은 나중에** 대입 |
| **변수 종류** | `val` (읽기 전용) | `var` (재할당 가능) |
| **값을 누가 넣나** | **자기 자신** (람다로 계산) | **외부** (DI/프레임워크/코드가 대입) |
| **언제 초기화** | 처음 접근하는 순간 자동 | 개발자/프레임워크가 대입하는 시점 |
| **초기화 전 접근** | 문제없음 (그때 계산됨) | 💥 `UninitializedPropertyAccessException` |
| **몇 번 계산/대입** | 딱 1번 (이후 캐시) | 몇 번이든 재대입 가능 |
| **타입 제약** | 아무 타입 (nullable 포함) | non-null만, **원시타입(Int 등) 불가** |
| **초기화 확인** | 불필요 | `::x.isInitialized` |
| **스레드 안전** | 기본 O (`SYNCHRONIZED`) | X (직접 관리) |
| **주 목적** | **비싼 계산 지연**(성능) | **나중 주입**(생명주기) |

## 2. 언제 쓰나 / 안 쓰나

| 도구 | ✅ 쓰는 상황 | ❌ 안 써도 되는 상황 |
|---|---|---|
| **`lazy`** | 무거운 자원(정규식·`ObjectMapper`·커넥션), 로거, 조건부로만 쓰는 비싼 파생 값 | 값이 가볍거나 항상 쓰는 경우 → 그냥 `val x = ...` |
| **`lateinit`** | 테스트 `@BeforeEach`, 안드로이드 `binding`, **필드 주입** `@Autowired` | **생성자 주입**(`val`) → 대부분의 스프링 코드 = 불필요 |

## 3. 판단 흐름 (3초 컷)

```
값을 지금 정할 수 있나?
 ├─ 예 → 그냥 val x = 계산()           (lazy/lateinit 둘 다 불필요)
 └─ 아니오, 미뤄야 한다
        누가 미루나?
         ├─ 내가 계산을 미룸(비싸서)   → by lazy { }
         └─ 남이 나중에 값을 주입함     → lateinit var
                                          (단, 생성자 주입 가능하면 val로!)
```

## 4. 한 문장 요약
- **`lazy`** = "비싼 걸 **늦게**, 그리고 **딱 한 번**." (내가 계산)
- **`lateinit`** = "지금은 없지만 **곧 누가 넣어줌**." (남이 주입 · 생성자 주입 불가할 때의 탈출구)
