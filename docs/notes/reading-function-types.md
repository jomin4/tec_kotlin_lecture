# 🧠 함수 타입 코드를 볼 때 머릿속에 떠올려야 할 것

`block: () -> Int` 같은 코드를 봤을 때, 순식간에 이렇게 "번역"되어야 한다.

## 1. 눈으로 읽는 순서

```
fun measure ( block : () -> Int ) : Int
              └─①─┘  └───②───┘   └③┘
```
- **① `block`** → "이건 **매개변수 이름**. 근데 담긴 게 값이 아니라 **함수**구나."
- **② `() -> Int`** → "**함수 타입**. `(` `)` 안이 **받는 것**(없음), `->` 뒤가 **주는 것**(Int).
  → 즉 '**아무것도 안 받고 Int를 돌려주는 함수**'."
- **③ `: Int`** → "이건 measure **자신의** 반환 타입."

## 2. 즉시 떠올릴 3장의 그림

`block: () -> Int` 를 보면 동시에 이 세 가지가 떠올라야 한다:

1. **의미**: "동작(함수)을 **매개변수로 받는다**. measure는 뼈대만 있고, 알맹이는 밖에서 꽂힌다." (= 구멍)
2. **사용**: 함수 안에서 **`block()`** 이라고 쓰면 → 넘어온 그 함수를 **실행**한다.
3. **정체**: 뒤에서는 **`invoke()` 메서드 하나짜리 객체**(Function0). `block()` = `block.invoke()`. (JVM이 함수를 몰라 객체로 포장)

## 3. 호출하는 쪽에서 떠올릴 것

```kotlin
measure { 40 + 2 }
```
→ "`() -> Int` 자리에 **람다를 꽂는다**. `{ 40 + 2 }` = '아무것도 안 받고 42를 주는 함수' → 타입이 맞다.
   마지막 인자가 람다라 **괄호 밖으로**(트레일링 람다)."

## 4. 함수 타입 읽기 표 (괄호=받는것 / 화살표뒤=주는것)

| 코드 | 머릿속 번역 |
|---|---|
| `() -> Int` | 안 받고 Int 줌 |
| `(Int) -> Int` | Int 받아 Int 줌 |
| `(String, Int) -> Boolean` | String·Int 받아 Boolean 줌 |
| `() -> Unit` | 안 받고 아무것도 안 줌 (자바 void) |
| `T.() -> R` | (수신객체 지정) this로 T를 쓰며 R 줌 — 스코프함수 apply/run |

## 한 문장 요약
**`파라미터명 : (받는것) -> (주는것)` → "이 자리에 동작(람다)을 꽂아라. 안에서 `()`로 실행한다. 뒤에선 invoke() 객체다."**
